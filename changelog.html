Changelog

31 Aug 2026
Product polish v0.4.0

Wantt starts to feel like Wantt

Build 8 was the first deliberate product-quality pass across the main Wantt experience. The foundations were already working; this release focused on making the app clearer, more useful and much closer to the product we actually want people to use.

  • Renamed Trips to Plans across the user-facing experience
  • Redesigned the Saves and Plans overviews for a denser, more content-first library
  • Cleaned up primary navigation, back behaviour and screen hierarchy
  • Reworked Save Detail so useful place, things-to-try and Plan information leads, with Instagram treated as supporting source content
  • Polished Plan Detail across both List and Map views, including a new Wantt map-marker treatment
  • Added the updated Wantt app icon to the real TestFlight build
  • Established a backend-first production verification process for future releases that change APIs or data models

The release passed its wider physical-iPhone review: existing Saves and Plans survived the upgrade, Share Sheet capture and enrichment continued to work, the new detail hierarchy held up on-device, and the map interactions behaved as intended.

One issue did survive the release. Manual Plan reordering did not work reliably on a physical iPhone. A replacement TestFlight binary — Build 9 — was produced to address it, but the behaviour remained effectively unchanged. Rather than keep burning release cycles on a non-critical bug, v0.4.0 was accepted with Plan reordering recorded as a known issue and deferred to the next build.

Next: fix Plan reordering, then keep improving the reliability and intelligence behind what a save can become.

30 Aug 2026
Account foundation v0.3.0

Wantt gets real user accounts

Build 7 gives Wantt its first proper account foundation. Sign in with Apple is now part of the TestFlight app, while the experience remains local-first and still works without forcing people through a login wall.

  • Sign in with Apple is now available in Settings
  • Existing Saves and Trips stay intact when you sign in or out
  • Anonymous use still works, and signing back in with the same Apple Account returns you to the same Wantt account
  • Behind the scenes, account ownership, diagnostics and app-to-server checks were hardened so multiple testers can use Wantt safely and failures are easier to diagnose

Engineering and deployment are complete, and the main production journey has passed on the first physical iPhone: share a new Reel, see it save immediately, enrich it, reopen the app and find the result still there.

Build 7 is conditionally accepted for now. The remaining check is deliberately simple but important: put the same TestFlight build on a second person's iPhone and confirm that the two users' Wantt data stays separate. That test is waiting on Apple's external TestFlight review.

Next: finish the two-user check, then start making Wantt feel much more like the product it wants to become.

28 Aug 2026
Product foundation v0.2.0 → v0.2.1

A save can become more than one thing

The biggest change so far was mostly under the surface. Wantt's original model treated a saved post as something fairly simple, often a single place. Real saves are not that tidy.

We rebuilt the underlying model so one post can contain multiple recommendations and things worth trying, while different shares of the same source can converge on the same canonical content. The app also moved onto a new versioned API with richer place information. That work first shipped as v0.2.0, with the release closeout landing as v0.2.1.

  • Support multiple recommendations and things to try from a single saved post
  • Added canonical saves and stronger duplicate handling
  • Moved the app onto the new /v2 data path
  • Added richer place metadata, including opening hours and open-now state
  • Kept the previous TestFlight build compatible while the backend changed underneath it
  • Completed a release closeout and regression pass before accepting the new release state

Getting there exposed an important distinction between merged and shipped. Some of the new code initially landed while the production backend was still running an older deployment, which left real saves stuck looking for a place match. Redeploying the current backend brought the product back into sync without requiring another TestFlight build.

Next: spend less time rebuilding foundations and more time using Wantt as a real product.

26 Aug 2026
Website

wantt.io is live

The first public home for Wantt is online. It is intentionally simple for now: a place to explain the idea, keep a changelog, and point toward the App Store launch.

  • Launched wantt.io on GitHub Pages
  • Added the first Wantt visual identity and bookmark mark
  • Added light and dark mode styling
  • Added Privacy, Terms and Support placeholders ahead of App Store submission

Next: keep iterating on the product in TestFlight and make the public site evolve alongside it.

25 Aug 2026
Milestone

First TestFlight build

Wantt moved from a private web prototype into a working iPhone beta. The core loop now works end to end: save a social post, extract what is useful inside it, and come back to it later in a form that is easier to use.

  • Share Instagram posts directly into Wantt from the iOS Share Sheet
  • Extract public post metadata and captions
  • Use AI to identify places, venues and useful context
  • Open extracted places in Google Maps
  • Detect duplicate saves
  • Remove saved posts
  • Support light and dark mode

Next: use it heavily, find the friction, and improve the save-to-use loop before App Store submission.
